# Security policy

## Report privately

Email [security@claviron.dev](mailto:security@claviron.dev) with the subject
`[SECURITY] Claviron`.

Do not disclose a suspected vulnerability in a public issue, pull request, or
discussion. If you are unsure whether a bug is security-sensitive, report it
privately first.

## What to include

- Affected crate, version or commit, enabled features, and operating system.
- A minimal reproduction and the configuration needed to trigger it.
- Expected behavior, observed behavior, and the potential security impact.
- Relevant logs or a proposed fix, if available.

Use synthetic data. Remove credentials, private keys, tokens, and personal data
from attachments. Identify any affected companion project or dependency too.

## Disclosure

Maintainers will review the report privately and coordinate a fix and public
disclosure with the reporter. Keep exploit details private while that work is
being coordinated.

Test only systems you own or have permission to assess.
